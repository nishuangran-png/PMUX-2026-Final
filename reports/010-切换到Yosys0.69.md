# 010 · 切换到 Yosys 0.69 并整体重测

日期：2026-10-14 凌晨
决定：项目工具链从 Yosys **0.68+27**（OSS CAD Suite 2026-08-06）切到 **0.69+117**
（OSS CAD Suite 2026-09-22）——团队在 Windows 上用的就是这一版。

## 安装结果

```
tools/oss-cad-suite/        Yosys 0.69+117   EQY v0.69-1-g7a92d84   ← 现役
tools/oss-cad-suite-068/    Yosys 0.68+27                            ← 并存，便于对比
YOSYS_VERSION               0.69                                     ← 全项目唯一版本来源
```

安装流程（`scripts/install_069.sh`）：分片字节数校验（521342093）→ 合并 →
`tar -tzf` 全量解压流校验 → 旧版改名并存 → 解包 → `yosys -V` 自检。
本机体检 `bash scripts/doctor.sh`：**22 项全过**；插件 `bash plugin/build.sh` 在 0.69 头文件下重建成功。

下载踩的坑：国内镜像（gh-proxy.com）对新连接给 300+ KB/s，但会把长连接降到几 KB/s。
解决办法是「卡住就重启续传」（`scripts/download_069_resume.sh`，断点续传只损失几秒），
实测 2.5 分钟补完最后 44 MB。

## 四个口径整体重测（13 个用例）

| 口径 | 0.68 基准→优化 | 0.69 基准→优化 | 结论 |
|---|---|---|---|
| `default`（官方 `synth`，门级 cell） | 5311 → 4054（−23.7%） | 5308 → 4122（**−22.3%**） | 略降，仍超满分线 |
| `mux_keep`（推荐流程） | 5227 → 2829（−45.9%） | 5227 → 2831（**−45.8%**） | 基本不变 |
| `gate_area` | 5464 → 5433（−0.6%） | 5449 → 5404（−0.8%） | 仍为反面对照 |
| `lut_area`（K=6 LUT） | 2216 → 2201（−0.7%） | 2213 → 2199（−0.6%） | 仍无收益（风险未变） |

**结论：结论不变，可以放心用 0.69。** 两个口径的差异都在 1.5 个百分点以内。

## 上游对比（0.69）

`python3 scripts/bench_upstream.py`：

| 做法 | 合计 | 相对默认流程 |
|---|---|---|
| 默认 `synth` | 5308 | — |
| 插一步上游 `pmuxtree` | 4565 | −14.0%（0.68 时是 −11.2%，**0.69 的上游更强了**） |
| 本算法 `pmux_opt` | 4122 | **−22.3%** |

即：即便上游在 0.69 里吃得更多，本算法仍比它再多 **−9.7%**。

## 需要记住的差异

- 0.69 的默认 ABC 对**大规模规则 mux 树**的处理与 0.68 不同：
  `scale_case64` 优化后从 0.68 的 936 变成 973；`scale_case16` 从 340 变成 350。
  这也是默认口径降幅从 −23.7% 略降到 −22.3% 的原因。推荐流程（mux_keep）不受影响。
- 所有历史报告里的数字都是各自版本下测的，报告开头都标了版本；跨版本比较只在本文件里做。
