# 003 · macOS 环境搭建与基线复现

日期：2026-09-24
工具：OSS CAD Suite `2026-08-06`（**Yosys 0.68+27**）
平台：macOS 14.8.8 · Apple Silicon（arm64）· 8 核 · 8 GB 内存

> 目的：把上一阶段在 Windows 上得到的环境与基线数据，在 macOS 上原样复现一遍。
> 复现通过才说明这台机器可以接后续的摸底实验和 C++ 插件开发。

## 一、环境搭建

工具链装在 `tools/oss-cad-suite`（`tools/` 已在 `.gitignore` 中，不入库）。

```bash
python3 scripts/download_suite.py \
    --date 2026-08-06 --platform darwin-arm64 --dest ./tools --proxy ""
tar -xzf tools/oss-cad-suite-darwin-arm64-20260806.tgz -C tools/
source tools/oss-cad-suite/environment
```

`yosys -V` 报告：

```
Yosys 0.68+27 (git sha1 72ce1b63d-dirty, Release, Clang ...)
```

与 Windows 侧使用的构建**完全同一版本**，这是两组数据可比的前提。

### 踩坑：直连 GitHub 下载太慢

`scripts/download_suite.py` 直连 GitHub release，实测只有 **44 KB/s**，
516 MB 的包要跑近三小时；且下载到中途会掉到 15 KB/s 左右。

改用 GitHub 镜像（实测 `gh-proxy.com` 单连接有 4.5 MB/s），再用多分片并发，
几分钟即可下完。下载完成后按字节数校验（`515952883`）并用 `tar -tzf` 验完整性。

**建议**：给 `download_suite.py` 加一个 `--mirror` 参数，别让队友在国内网络下重复踩这个坑。

## 二、基线复现

命令：`yosys -p "read_verilog <用例>; synth -top <模块>; stat"`

| 用例 | 本机实测 | 001 记录值 | 一致 |
| --- | --- | --- | --- |
| `pmux_basic` | 132 | 132 | ✅ |
| `pmux_onehot` | 132 | 132 | ✅ |
| `pmux_priority` | 128 | 128 | ✅ |
| `mux_tree_8to1` | 56 | 56 | ✅ |
| `pmux_in_alu` | 207 | 207 | ✅ |
| `pmux_nested` | 112 | 112 | ✅ |

`proc; opt_clean` 之后的 RTLIL 结构也逐项对上：

| 用例 | 本机实测 | 001 记录值 |
| --- | --- | --- |
| `pmux_basic` | `$eq`×7 `$logic_not`×1 `$pmux`×1 | 一致 |
| `pmux_onehot` | `$eq`×7 `$logic_not`×1 `$not`×1 `$pmux`×1 | 一致 |
| `pmux_in_alu` | `$eq`×6 `$logic_not`×1 `$pmux`×1 + `$add`/`$sub`/`$and`/`$or`/`$xor`/`$gt` | 一致 |
| `pmux_nested` | `$eq`×6 `$logic_not`×3 `$not`×2 `$pmux`×3 + `$add` | 一致 |
| `pmux_priority` | `$mux`×8 | 一致 |
| `mux_tree_8to1` | `$mux`×7 | 一致 |

含 `$pmux` 的用例 4 个、合计 **6 个 `$pmux` 结构**，与 001 的统计相同。

## 三、三个关键数字复现

| 实现方式 | 单元数 | 相对默认 |
| --- | --- | --- |
| 默认流程 `synth` | 132 | 基准 |
| 插入一步 `pmuxtree` | **103** | 缩减 22% |
| 显式 mux 树 `mux_tree_8to1` | **56** | 缩减 58% |

其中 103 这条此前只记了结论、没记命令，本次确定了能复现它的完整命令
（`pmuxtree` 必须在技术映射之前调用，跑在 `synth` 之后无效）：

```
read_verilog rtl/single/pmux_basic.v; proc; opt; pmuxtree; synth -top pmux_basic; stat
```

对照：把 `pmuxtree` 放到 `synth` 之后，单元数仍是 132，说明这条命令的作用位置是关键。

## 四、EQY 等价验证复现

```bash
cd experiments/eqy-demo
source ../../tools/oss-cad-suite/environment
eqy eq_ok.eqy    # 预期通过
eqy eq_bad.eqy   # 预期被找出反例
```

| 用例 | 结果 | 关键输出 |
| --- | --- | --- |
| `eq_ok.eqy` | **PASS** (rc=0) | `Induction step proven: SUCCESS!` |
| `eq_bad.eqy` | **FAIL** (rc=2) | `SAT temporal induction proof finished - model found for base case: FAIL!` |

反例波形已导出：`experiments/eqy-demo/eq_bad/strategies/pmux_demo.y/sat/trace.vcd`

两条关键输出与 `PMUX综合优化选题首次汇报.docx` 里引用的完全一致。

**Windows 上的「缺 make」坑在 macOS 上不存在**：EQY 的最后一步
`make -C <workdir> -f strategies.mk` 正常执行（用的是 Xcode 命令行工具自带的
GNU Make 3.81），五步全自动跑通，不需要像 Windows 那样手工绕过。

`PYTHONUTF8=1` 在 macOS 上不是必需的，但设上无害，为保持两边命令一致可以保留。

## 五、结论

1. 这台 Mac 的工具链与 Windows 侧**逐项一致**，包括版本号、6 个用例的单元数、
   RTLIL 结构和三个关键数字。
2. 官方指标里的「132 → 56」空间判断，在 macOS 上成立。
3. EQY 全自动流程在 macOS 上开箱可用，**回归脚本可以直接在这台机器上建**。
4. 后续摸底实验（逐个禁用 `opt_muxtree` / `pmux2shiftx` / `muxcover`）
   现在可以开始跑了。
