# 028 · 平台边界、长优先级链与真实千级封存集（2026-10-24）

## 1. 一句话结论

外部纯 RTL 用例**不会因为来自 macOS/Linux 或别的 FPGA 工程就天然无效**。真正决定它能否
用于本项目泛化验证的是：Yosys 0.69 能否解析、能否按 Cyclone IV 映射、是否依赖厂商黑盒/IP、
能否做 EQY。外部用例永远不能计入官方四题成绩，只用于暴露泛化风险。

本轮封存集实测没有支持“当前算法已经全面泛化”的说法：

- 5/8/16 级自行构造链有收益，但 6 级链从 112 变成 114；
- 外部 `verilog-axi` 的 priority encoder/arbiter 基本持平；
- 真实 CPU `picorv32` 从 2109 变成 2130（面积反增 1.00%）；
- 外部 512 路 priority encoder 达到 1346 个逻辑单元，EQY 通过，但它同时说明“千级可验证”
  不等于“千级有优化收益”。

## 2. 平台边界

这里必须区分四件事，不能混成一个“平台”：

| 概念 | 本项目的实际情况 | 对测试用例的含义 |
|---|---|---|
| 当前开发机 | macOS 14.8.8 / arm64，本机构建 Yosys 0.69 | 只用于开发、回归和证据收集 |
| 正式验收运行环境 | Windows 原生，入口调用 `yosys.exe`；WSL 可用于开发但不能替代正式入口 | Mac/Linux 结果不能直接写成 Windows 验收结果 |
| 逻辑映射目标 | `synth_intel -family cycloneiv` 生成的 Cyclone IV 网表 | 不要求映射到实际 `EQ6HL130P-CSG484` 板卡 |
| eLinx | 选题二不需要 eLinx 工程、编译仿真或仿真报告 | 不能用“eLinx 不能跑”判断用例无效 |

官方依据：

- 答疑表第 8 行：选题二“统一映射为 cycloneiv 系列网表”；
- 答疑表第 66 行：选题二“不需要使用 elinx 编译仿真，工程以及仿真报告也无需提供”；
- 答疑表第 69 行：选题二评测“windows 版”；
- 答疑表第 106 行：官方基线是 Yosys 官网 0.69，不是 OSS CAD Suite；评测入口应调用 `yosys.exe`。

原文在 `archive/官方材料-20261020/FPGA创新大赛问题汇总-20261020.xlsx`。

## 3. 外部测试用例的有效性门禁

### 3.1 可以纳入泛化封存集

同时满足以下条件，平台来源不影响有效性：

1. 普通可综合 Verilog，或当前 Yosys 0.69 确实支持的 SystemVerilog；
2. Yosys 0.69 能完整解析层次，不依赖缺失的 include、黑盒或厂商 IP；
3. `synth_intel -family cycloneiv` 能完成综合；
4. 能生成用于 EQY 的网表，且没有未解释的 `$lut`、黑盒或不可观察状态；
5. 清单提前固定仓库 URL、commit、许可证、顶层模块和参数。

外部用例的收益、持平或回退都必须如实记录。外部用例不进入比赛的四个公开用例统计。

### 3.2 不能原样纳入

| 情况 | 判定 |
|---|---|
| Xilinx/Intel 专有原语、厂商 RAM/DSP/IO 黑盒 | 原样无效；没有兼容库就不能证明 Cyclone IV 下的功能 |
| 板级顶层、引脚约束、时钟/复位 wrapper 占主导 | 原样无效；可另做“只取纯逻辑核”的适配版并明确标注 |
| 当前 Yosys 前端不支持的语法 | 原样无效；不能通过改源代码后仍宣称是原用例 |
| 加密 IP、只有网表没有可审计 RTL | 不能做本项目的源到网表 EQY |
| 仅能在某个仿真器或商业综合器中运行 | 不具有本赛题工具链的可复现性 |

“无效”只表示**不能作为该用例原样的证据**，不表示其中的设计思想没有参考价值。

## 4. 冻结清单与来源

清单：`experiments/holdout-20261024/manifest.json`。

复现来源可用 `scripts/fetch_holdout_20261024.sh`；默认下载到 `tools/holdout-20261024/sources`，
也可用环境变量 `FPGA_HOLDOUT_ROOT` 指向自己的缓存目录。

固定构建：

- Yosys 0.69 commit：`9f75ca1f9834a39a863915b5dae0c7b1e33533bc`；
- 基线二进制 SHA-256：`64c2b1f49272c5b5fa89be0c7d3f9460db86c34250321c1b75c3a557960df488`；
- 候选二进制 SHA-256：`904556b188b3753520e702a0b8d3940326154187ec085bf6e940f421417b9b45`；
- 映射口径：`synth_intel -family cycloneiv`；
- 面积口径：`cycloneiv_lcell_comb + $not`。

复跑命令：

```bash
FPGA_HOLDOUT_ROOT=/tmp/fpga-holdout-20261024/sources \
python3 scripts/eval_holdout.py \
  --manifest experiments/holdout-20261024/manifest.json \
  --json reports/028-封存集评测.json \
  --timeout 600
```

执行顺序固定为“全部用例先跑基线 → 全部用例再跑候选 → 最后做 EQY”；清单顺序、失败样本和
零收益样本全部保留。JSON 中记录清单里的可移植来源路径和每个源文件的 SHA-256，不写死本机缓存目录。

## 5. 实测结果

本表在 macOS 上运行，只作为开发期证据，不是 Windows 正式效率成绩。

| 用例 | 类型 | 基线 | 候选 | 缩减率 | DFF | EQY |
|---|---|---:|---:|---:|---:|:---:|
| 5 级优先级链 | 自行构造 | 96 | 82 | +14.58% | 0→0 | PASS |
| 6 级优先级链 | 自行构造 | 112 | 114 | **−1.79%** | 0→0 | PASS |
| 8 级优先级链 | 自行构造 | 160 | 121 | +24.38% | 0→0 | PASS |
| 16 级优先级链 | 自行构造 | 336 | 262 | +22.02% | 0→0 | PASS |
| priority encoder WIDTH=16 | 外部 | 34 | 34 | 0.00% | 0→0 | PASS |
| priority encoder WIDTH=128 | 外部 | 307 | 307 | 0.00% | 0→0 | PASS |
| priority encoder WIDTH=512 | 外部 | 1346 | 1346 | 0.00% | 0→0 | PASS |
| arbiter PORTS=64 | 外部 | 172 | 172 | 0.00% | 71→71 | PASS |
| picorv32 默认参数 | 外部 | 2109 | 2130 | **−1.00%** | 597→597 | 未跑 |

原始 JSON：`reports/028-封存集评测.json`。

说明：

- 6 级链和 `picorv32` 的回退不是“结果不好就删”的理由，正好是下一步需要定位的泛化缺口；
- `picorv32` 的 EQY 尚未完成，所以不能把它的面积结果包装成“正式泛化已通过”；
- priority encoder WIDTH=512 是真实外部模块且超过 1000 个逻辑单元，EQY 通过，说明封存集
  至少有一个真实千级等价验证样本；但候选没有任何面积收益，不能据此宣称现有算法泛化良好。

## 6. 下一步

1. 先定位 6 级链为什么比基线多 2 个逻辑单元：重点检查“一条 `$pmux` 重写”与 ABC 映射的
   组合是否反而扩大了面积。
2. 对 `picorv32` 做分模块或整体 miter 的等价验证；若成本过高，应明确标注“仅面积样本”，
   不能把未验证结果升级为 PASS。
3. 只有在不损害 5/8/16 级链、官方四题和 `picorv32` 的前提下，才调整算法；任何修改放入
   独立实验分支，保留修改前后原始数据。
4. Windows 原生 `yosys.exe` 的面积、EQY 和 PowerShell 计时仍需单独复测。本报告的 Mac
   运行时间不能替代正式验收。

## 7. 对外表述

可以这样说：

> 外部纯 RTL 用例与操作系统无关，只要通过 Yosys 0.69、Cyclone IV 映射和 EQY 门禁，就可以
> 作为泛化验证。但它不能计入官方四题成绩。我们已用真实外部千级用例做过测试，发现部分用例
> 持平、部分回退，说明当前算法还需要继续提升泛化性。

不能说：

> 找到外部大用例，所以隐藏用例也能达到 20%；或者 Mac 上跑通，所以 Windows 验收也一定通过。
