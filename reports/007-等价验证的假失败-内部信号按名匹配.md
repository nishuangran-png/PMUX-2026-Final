# 007 · 等价验证的假失败：EQY 会按名字匹配内部信号

日期：2026-10-13 夜
结论先说：**pmux_onehot 那次 FAIL 不是功能不等价，而是我们在门级网表里留下了一条悬空的命名 wire，被 EQY 当成了额外的等价点。**

## 现象

`scripts/regress.sh` 里 6 个用例，只有 pmux_onehot 报 FAIL。看 EQY 自己的日志：

```
[eq] run: Could not prove equivalence of partition 'pmux_onehot.sel.0'
[eq] run: Proved equivalence of partition 'pmux_onehot.sel.1'
```

注意分区名是 `pmux_onehot.sel.0` —— 不是输出端口 `y`，而是内部信号 `sel`。

SAT 给出的反例（摘录）：

```
\gold.sel   1       001        ← 金标准里 sel = addr ^ 101 = 1
\gate.sel   0       00         ← 门级网表里 sel 只剩 2 位、值 0
\__po_y__assert.okay  1        ← y 这一路是等价的
```

## 根因

1. EQY 默认会把两侧**同名的内部信号**也当成等价点：`eq/matched.ids` 里有 `pmux_onehot sel sel`，
   `eq/partition.list` 里就多出 `pmux_onehot.sel.0` 这一条分区。
2. 我们的 pass 把「`sel` → 8 个比较器 → `$pmux`」这一整块换成了直接由 `addr` 位驱动的 mux 树，
   产生 `sel` 的那段逻辑随之变成死逻辑。
3. 但 `sel` 是 RTL 里声明过的命名 wire，Yosys 默认**不会删掉命名 wire**（只删死单元）。
   `proc` 阶段留下的 `connect sel[1] = addr[1]` 还在，于是门级网表里 `sel` 成了一条只驱动 1 位的悬空线。
4. EQY 把这条悬空线和金标准里语义正确的 `sel` 一比，必然不等价 → 报 FAIL。

换句话说：**功能是等价的，`y` 的断言也通过了；失败的是「结构上被当成等价点的中间信号」。**

## 修法

在产出网表的流程末尾加一句 `opt_clean -purge`，用 `-purge` 删掉没有用户的命名 wire：

```
read_verilog x.v; proc; opt; pmux_opt; synth -top x; opt_clean -purge; write_rtlil x.il
```

改完 6 个用例全 PASS，且单元数不变（pmux_basic 仍是 132 → 56）。

验证方法（保留中间文件，便于复现）：

```bash
PMUX_KEEP_TMP=1 bash scripts/regress.sh
# 然后看 $WORK/eq_<用例>/eq/partition.list 和 matched.ids
```

## 教训（写进项目规范）

- 任何「改写网表」的 pass，交付前都要想一遍：**被删掉的那段逻辑，有没有留下命名 wire？**
  命名 wire 悬空不但浪费 EQY 的时间，还会制造假失败。
- 看到 EQY FAIL 先别慌着改算法：先看是哪个 partition 失败。
  - 分区名是输出端口 → 真·功能不等价，必须修；
  - 分区名是内部信号 → 先查它是不是变成了悬空线。
- 等价验证的口径要在报告里写清楚：我们验证的是「模块所有输出端口 + 所有同名内部信号」，
  后者其实比「只看端口行为」更严格，是好事；但必须保证网表干净。
