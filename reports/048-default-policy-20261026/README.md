## 算法改动

### 1. 稠密 PMUX 使用宽度相关的默认树顺序

原 4 例上的经验是：先消掉“每个代码值一个比较器”的译码结构，再交给
ABC 映射，比让 techmap 重建译码器更省 LUT。本轮保留这一原则，但对
`$pmux` 替换树增加结构化的 `auto` 顺序：

- 总线宽度 `<= 2` 时低位优先；
- 更宽的总线保持高位优先。

这是根据选择总线位宽选择树形，不读取文件名、模块名或 case 编号。
case03 因此从 `319` 再降到 `317`。

### 2. 同一运算符分支的选择后因子化

当稠密 PMUX 的所有叶子都是同一种可交换/逐位运算符（如 XOR、ADD、
OR、AND、SUB），且至少有两个不同的物理运算符实例时，先分别选择
两侧操作数，再只保留一个运算符：

```text
mux(s, a0 op b0, a1 op b1, ...) -> mux(s, a0, a1, ...) op
                                      mux(s, b0, b1, ...)
```

这是原 4 例成功经验在新增用例上的直接推广。case03 的 XOR、ADD、SUB
分支两两命中，是 `409 -> 317` 的主要来源。

### 3. 深链守卫改为“分支独立”判据

此前为避免重写串联反馈链造成面积回退，只要数据锥较深就跳过。本轮
只放宽一种结构：一个 PMUX 的多个直接 PMUX 前驱彼此不在对方的数据锥
中。此时它们的嵌套是兄弟分支，可以安全进入树形重写；如果存在串联
依赖，仍保持跳过。

该判据只看单元连接关系：

- case05 的嵌套 PMUX 是兄弟分支，允许重写，`398 -> 386`；
- case04 的高层 PMUX 依赖同链传上来的 PMUX，继续跳过，避免回退。

### 4. 默认值固化

最终正常运行不依赖环境变量。`pmux_opt` 默认使用：

- `dense_style=auto`
- `factor_ops=1`
- `skip_deep=1`
- `deep_threshold=2`
- `deep_policy=independent`

`PMUX_*` 环境变量仅保留作消融实验，不参与按用例选策略。

## 效率

新增 5 例各交替运行 10 次，统计完整 `synth_intel` 的墙钟、CPU 和峰值
RSS 中位数：

- 五例墙钟合计：`1.494 s -> 1.388 s`，约快 `7.1%`；
- 五例 CPU 合计：`1.38 s -> 1.27 s`，约减少 `8.0%`；
- 最大单例墙钟比：`1.004`；
- 最大单例 CPU 比：`1.000`；
- 最大单例 RSS 比：`1.073`，出现在 case05，仍低于 `1.15` 零分线。

以上是 Apple Silicon macOS 本机数据，不能直接外推到 Windows/WSL 或
Elinx；最终仍应在目标环境复测。

## 边界与后续

1. 当前算法解决的是可识别的稠密译码 PMUX，而不是任意 PMUX 网络。
2. case04 的串联反馈链和 case05 的小面积收益仍是弱项。
3. 35 例公开 RTL 只能说明当前封存集无回退，不能宣称无边界泛化。
4. 若继续提高泛化性，下一步应优先加入按结构成本预测决定是否重写，
   而不是继续增加按 case 或参数写死的开关。
