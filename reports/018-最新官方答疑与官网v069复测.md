## 一、最新答疑新增了什么

新版答疑共新增 10 条，其中 6 条直接涉及赛题二：

| 主题 | 官方答复 | 对项目的影响 |
|---|---|---|
| Baseline 版本 | `0.69` 即可，来自 Yosys 官网 GitHub，不是 OSS CAD Suite | 必须用官网 tag `v0.69` 的源码和二进制重新评测 |
| Windows 计时 | 使用 PowerShell `Measure-Command` | 不再依赖 Yosys 内部打印精度，也不再自行补计时代码 |
| ABC/techmap | 可以在 0.69 上修改 ABC 脚本，techmap 也可基于该版本修改 | 允许在官方版本基础上做流程优化，但必须同源对照 |
| 效率评分 | 所有用例 CPU 与峰值内存均不超过原版 1.05 倍为满分；任一项超过 1.15 倍则效率项 0 分 | `test2` 当前内存超标，效率不能宣称满分 |
| 测试集 | 会增加效率测试用例 | 不能再只针对现有四题调优，必须做泛化与预回归 |
| 最终入口 | WSL 提交物最终也应调用 `yosys.exe` | Windows 原生构建与运行必须单独验证 |

另有一条说明：EQY 脚本由参赛队自行编写，只用于证明功能正确，不属于正式面积/效率计时。

## 四、效率复测（修复前）

官网答疑采用 PowerShell `Measure-Command`，因此本轮额外记录墙钟时间和峰值 RSS。
每轮交替运行原版和优化版，取 15 次中位数：

| 用例 | 墙钟原版→优化 | 比值 | RSS 原版→优化 | 比值 |
|---|---:|---:|---:|---:|
| test1 | 0.230 → 0.200 s | 0.870 | 24.14 → 23.31 MB | 0.966 |
| test2 | 0.080 → 0.080 s | 1.000 | 17.39 → 21.23 MB | **1.221** |
| test3 | 0.090 → 0.090 s | 1.000 | 20.88 → 18.56 MB | 0.889 |
| test4 | 0.110 → 0.110 s | 1.000 | 22.44 → 22.28 MB | 0.993 |

结论：

- 时间项四个现有用例均不超过原版；
- `test2` 峰值内存约为原版的 **1.22 倍**，超过官方 1.15 线，效率项目前按规则会得 0 分；
- 官方会新增效率用例，因此即使修好 `test2`，也还需要对更大规模、不同 PMUX 形态做预回归；
- 当前面积结果达标，但不能写成“效率满分”或“综合双满分”。

本节记录的是问题发现时的旧方案。随后已将 4 级优先级链改成平衡 mux 树，修复后
`test2` 的内存比降到 `1.002`（15 次）和 `0.974`（31 次），详细数据见
`reports/019-test2平衡mux树.md`。

## 五、安装脚本修复

本轮发现 `scripts/install_pmux_069.sh` 在源码包目录中会被外层仓库的 `.git`
误判为 Git 工作树，导致补丁“看似成功”但没有写入目标源码。现已改为只在源码根目录
本身是 Git 仓库根时使用 `git apply`，否则使用 `patch`。该问题曾使第一次官网源码
构建得到 0% 的假结果，现已在重新构建后排除。
