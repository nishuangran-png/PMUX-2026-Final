# 这个项目到底要解决什么问题（通俗版）

> 用途：给队友、指导老师、答辩评委用的一页纸说明。报名简介 / 开题报告都能从这里改写。

## 一句话

**让 FPGA 的综合工具在"多路选择"这类电路上少用一点硬件资源，同时保证电路功能一个字都不变。**

## 先说背景：什么叫"综合"

写 FPGA / 芯片，先写 Verilog（人话版的电路描述），再由工具把它翻译成一张**电路单元清单**——这张清单叫"网表"。

清单上每个单元（LUT、触发器、与门、或门……）都要占芯片上一块真实的硅片面积。所以清单越短越好：

- **单元越少 → 芯片面积越小 → 成本越低**
- **单元越少 → 延迟越小 → 跑得越快**
- **单元越少 → 功耗越低**

综合工具的一个核心任务就是：把同一份 Verilog 翻成一张**尽量短**的清单。这个项目就是在这个环节上做优化。

## 问题出在哪：多路选择器（MUX）

**MUX = 电路里的多岔路口。** 一堆数据线摆在那儿，控制信号说"走第 3 路"，就只让第 3 路的信号过去。

它在电路里**无处不在**：CPU 的寄存器堆读写、总线切换、状态机输出、DSP 数据通路、译码逻辑……一个中等规模的数字电路里，MUX 经常是数量最多的组合逻辑结构之一。

**为什么它费资源？** 假设你要从 100 路信号里选 1 路：

- 工具最"保险"的搭法是**串成一棵二叉树**：2 路合一，4 路合一，8 路合一……100 路要约 **99 个二选一开关**，在 FPGA 里差不多吃掉 **99 个查找表（LUT）**。
- 但如果换个搭法——**移位器**（一路一路挪过去）、**与或结构**（谁被选中谁开门）、**译码器 + 覆盖逻辑**——同样的功能可能只要**一半甚至更少**的单元。

关键点：**能不能省，取决于控制信号有什么性质**。控制信号是不是同一时刻只有一个有效（one-hot）？是不是几个信号天然互斥、永远不会同时为 1？有没有"这种情况随便输出什么都行"的无关项（don't care）？

- 知道这些性质 → 可以大胆换搭法，省下大片面积
- 不知道 → 只能老老实实搭成树，资源就这么浪费掉了

**PMUX**（parallel mux）就是 Yosys 里用来表示"多路、可能有多个分支同时成立"的那种 MUX 单元类型，是本次优化的主要目标。

## 现有工具为什么没解决

Yosys（开源综合工具，本次比赛指定的开发框架）**已经有**一堆跟 MUX 有关的优化流程：`opt_muxtree`、`pmux2shiftx`、`muxcover`、`pmuxtree`、`opt_reduce`、`opt_share`……

但它们各有各的前提和局限，尤其是在这几种情况下留了优化空间：

1. **嵌套的 PMUX**——MUX 的输出又接了另一层 MUX，工具逐层看，看不到整体
2. **混合组合逻辑的 PMUX**——选择条件不是干净的信号，而是一小坨逻辑表达式
3. **带 don't-care 的控制信号**——工具不敢用"随便什么都行"这条信息去简化
4. **多条分支可能同时有效**——不是标准 one-hot，常规优化直接放弃

> ⚠️ 这一条是**需要我们用实验证实的假设**，不是已知结论。上游工具已经做过很多，剩下的增量空间到底有多大，必须先用对照实验量出来。

## 我们具体要做什么

**交付物：一个 Yosys 自定义插件（自定义 Tcl 命令 / pass）。**

用法就是：把网表丢进去，它吐出一张更短的网表。

```
read_verilog 设计.v
hierarchy; proc; opt; ...     ← 常规综合流程
pmux_opt                       ← 我们写的这条命令
write_verilog 优化后的.v
```

算法分三步：

**第一步 · 识别**——在 Yosys 的中间表示（RTLIL）上做模式匹配，把"由 `$pmux` / `$mux` 及其组合构成的结构"找出来，圈成一个待优化的整体。

**第二步 · 分析**——看这些结构的控制信号有什么性质：互斥吗？one-hot 吗？有条件永远不出现吗？顺便建一个**成本模型**，能算出"用 mux 树实现要几个单元、用移位器要几个、用与或要几个"。

**第三步 · 重构**——按成本模型选最便宜的那种实现，把原结构原地换掉。

**全流程保险：EQY 形式等价验证。** 优化前网表 vs 优化后网表，工具自动证明"对所有可能的输入组合，输出完全一致"。这一步是硬性要求，见下。

## 怎么算做成了（官方指标）

| 指标 | 要求 | 满分线 |
|---|---|---|
| 电路单元数缩减 | ≥ 10% | ≥ 20% |
| 1000 节点电路优化耗时 | ≤ 60 秒 | — |
| 内存峰值 | ≤ 2 GB | — |
| 优化前后逻辑等价 | **必须通过 EQY 验证** | — |

**⚠️ 生死线：只要有一个测试用例不等价，功能正确性直接 0 分，其余各项也一律不计分——整个作品作废。**

所以等价验证环境必须在**第一天**就搭好，每次改动都跑一遍，不能等做完再补。

## 评分构成

| 项目 | 权重 |
|---|---|
| 功能正确性 | 10 |
| 面积优化效果 | 40 |
| 算法效率（时间 / 内存） | 30 |
| 文档 | 5 |
| 答辩 | 15 |

**面积优化占 40 分，是主战场。** 效率 30 分意味着"跑得又快又省内存"和"省的面积多"几乎同等重要——不能为了多省 1% 面积把耗时翻十倍。

## 需要先搞清楚的四件事（问组委会）

1. "电路单元"具体怎么计数？LUT？门？还是 RTLIL 里的 `$cell`？
2. 测试用例是官方发放，还是我们自造？
3. 对比基准（baseline）到底是哪条具体流程？
4. 指南前后矛盾：选题二正文写"Yosys + EQY"，末尾却写"全部通过 eLinx 编译仿真"——以哪个为准？

## 第一步做什么（两周摸底）

1. 搭好 Yosys + EQY 环境，跑通一个小设计
2. 造一批带 PMUX 的测试电路（mux 树、嵌套 mux、移位器、带 don't-care 的控制逻辑）
3. **逐个禁用**上游那些 mux 相关 pass，做对照实验，量出"默认流程到底还剩多少面积没榨干"
4. 得出一个数字：**我们有多少可做的空间**

这一步跑完，才能判断 10% / 20% 的目标是"稳"还是"悬"。如果不做这一步直接开写算法，很可能做到一半发现上游已经吃掉了，方向要推倒重来。

## 团队技术栈对照

- 需要：Yosys C++ pass 开发、RTLIL 中间表示、布尔逻辑化简、Tcl 命令、EQY
- 用不上：YOLO、神经网络训练——**这个选题不涉及 AI**
- 已有基础可复用：数字电路、Verilog、逻辑等价与真值表直觉、Linux/C++ 工具链
