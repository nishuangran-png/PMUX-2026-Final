日期：2026-10-27
分支：`codex/priority-tree-sharing-20261025`
目标：新增五例面积缩减达到 25%，主体算法有界迭代，九例共用核心算法。

## 1. 本轮完成

1. 把九例目标写成统一 manifest，固定 RTL 路径、顶层和 SHA-256，避免评测时切换样例。
2. 将 PMUX 主体改写改成有界固定点调度：
   - `-max_iterations` 默认 4；
   - 首轮执行一次优先级链和密集译码器归一化；
   - 后续轮只执行可由下游消费者消除的局部规则；
   - 零变化立即停止。
3. 九例实测均在 2 轮收敛，面积全部超过 25%。
4. 增加结构属性 `pmux_opt_restructured`，只在模块真的被改写时切换自定义 ABC；否则沿用
   官方 ABC9。
5. 从官网 0.69 干净源码重新安装、构建并回归九例，确认当前面积不是旧构建残留。

## 3. 问题定位

最终封存回归发现 `case_large__case_lage_top` 从 `638` 回退到 `663`。对比 custom ABC 与
ABC9 后确认，根因是未发生结构收益的模块也被切换到自定义 ABC，而不是 PMUX 改写本身。

修复没有使用模块名或文件名分支，而是由 `pmux_opt` 在模块发生实际变化时设置 RTLIL 属性；
`synth_intel` 只在该属性存在时选择自定义 ABC。修复后该例恢复 `638→638`，九例成绩保持不变。

## 4. 参考项目与取舍

下载并阅读了 mockturtle 与 phyLS 的 window resubstitution、DSD、LUT mapping 和 resub 文档。
两者没有直接接入正式候选：其数据结构与当前 Yosys 0.69 pass 接口不兼容，仓促引入会增加
构建、等价验证和内存风险，且没有在本项目九例上测到可证明收益。当前结论以已落地的结构
规则、固定点调度和 ABC 门槛为准，不用外部项目名义包装未集成代码。
