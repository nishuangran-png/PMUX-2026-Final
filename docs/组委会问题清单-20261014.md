## 1. 「电路单元」怎么计数？

**原问题**：是门级 cell 数（`$_AND_`、`$_MUX_` 之类）、LUT 数，还是 `stat` 输出的某个数字？

**为什么必须问**：口径不同，我们的优化效果差 45 个百分点。同一批 13 个用例实测：

| 口径 | 基准 | 加我们的 pass | 降幅 |
|---|---|---|---|
| 官方默认 `synth`（门级 cell） | 5311 | 4054 | **−23.7%** |
| 面积导向 + 保留 mux 结构的映射 | 5227 | 2829 | **−45.9%** |
| K=6 LUT 映射 | 2216 | 2201 | **−0.7%** |

原因：与或网络里的译码项能被 LUT6 吸收，而 mux 树每一级都要实打实占 LUT。
**如果按 LUT 口径算，我们目前的算法几乎没有收益**，需要提前知道并调整方向。

**应对**：若确认是门级 cell 数 → 按现状推进（已超满分线）；
若是 LUT 口径 → 需要改算法目标（例如只在 LUT 口径下也省的结构上下功夫）。

## 2. 「标准 Verilog PMUX 测试用例集」是官方提供还是自己构造？

**为什么问**：我们现在用自己构造的 13 个用例 + 112 个随机模糊测试用例（全部 EQY 等价）。
如果官方另有测试集，需要提前拿到，避免优化方向对不上。

**应对**：若官方提供 → 用官方集重跑并针对性调优；若自构造 → 在报告里说明用例覆盖
（宽度 2~6 位选择、全码/稀疏/default 多缺码、两级嵌套、与算术混排、多 mux 共享总线）。

## 3. baseline 具体是哪条流程？

**为什么问**：指南写「原始 Yosys 默认综合流程」，但 `synth` / `synth_xor` / `synth_xilinx`
差别很大；而且默认 `synth` 内置的 ABC 是**延迟导向**，会把规则 mux 树打散。

**我们实测到的关键事实**（可以作为提问依据）：
- 我们的 pass 输出 504 个 `$_MUX_`（64 路 × 8 位多路选择器的理论下界）；
- 走默认 `synth` 的 ABC：**980** 个单元；走面积导向映射：**432**；
- 只有最小化的面积导向脚本（`strash; &get -n; &nf -a; &put`）能原样保留 504。

**具体要问的**：
1. baseline 是 `synth`（不带参数）吗？版本号要求？是否允许在流程里替换 ABC 的映射脚本？
2. 我们的交付里带了一个推荐流程脚本（`scripts/pmux_synth.sh`），能不能按「插入自定义命令 + 保留其余默认流程」的方式计分？
3. 如果我们额外提供「自动选优」（两条流程都跑取更小者，最坏也不劣于基准），是否允许？

## 5.（新增）「自定义 Tcl 命令」是字面意义的 Tcl，还是 Yosys 脚本命令？

**背景**：指南写「在 Yosys 框架内新增自定义 Tcl 命令」。
我们实现的是一个 Yosys pass（`pmux_opt`），在 Yosys 脚本里就是一条命令：

```
read_verilog x.v; proc; opt; pmux_opt; synth -noabc -top x; ...
```

但**本机 OSS CAD Suite 的 Yosys 构建没有编 Tcl 支持**（没有 `tcl` 命令，
二进制也没有链接 libtcl）。如果组委会要求字面意义的 Tcl 交互，
需要另装带 TCL 的 Yosys 构建，或确认「命令」即可。

## 6.（新增）等价验证的口径

**背景**：EQY 默认会把两侧**同名的内部信号**也当成等价点。
我们的 pass 会删掉被优化掉的中间信号，如果网表里留下悬空 wire，
会出现「功能等价但 EQY 报 FAIL」的假失败（已定位并修复，见 reports/007）。

**要问的**：验收时的等价检查是「只看模块端口行为」，还是「端口 + 同名内部信号」？
如果是后者，我们交付的网表已经做到干净（产出前 `opt_clean -purge`），不会踩这个坑。
