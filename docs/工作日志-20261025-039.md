## 4. 回归定位与代码改动

### 4.1 现象

新封存集首轮发现：

- `muxpack__mux_if_unbal_5_3`：`17→20`；
- `muxpack__mux_if_unbal_5_3_width_mismatch`：`15→16`。

两条都不是 ROM 相关测试，问题定位到既有的优先级 `$mux` 链分组改写。

### 4.2 根因

当选择位是同一总线的 `$eq` 常量比较，且码值严格从 `N-1` 降到 `0` 时，原链已经是 ABC9
容易识别的规范结构。提前把链切成小组并增加共享 OR，会把控制网络固定成另一种形态，
在后续技术映射中反而得到更差的切分。

### 4.3 修复

`src/yosys-069/passes/pmux/pmux_opt.cc` 新增结构解析和门槛：

- `ChainCompare`、`decode_chain_compare()`：只解析 `$eq` 与全零 `$logic_not`；
- 要求比较总线位集合一致、码值严格为 `N-1..0`；
- 满足条件时保留原链交给 ABC9；
- 其它链仍走原有分组路径。

门槛不依赖模块名、文件名、测试编号或固定宽度。修复后：

- `mux_if_unbal_5_3` 回到 17；
- `mux_if_unbal_5_3_width_mismatch` 回到 15；
- `mux_if_unbal_5_3_order` 从 20 降到 15；
- `mux_if_unbal_5_3_nonexcl` 从 16 降到 12。
