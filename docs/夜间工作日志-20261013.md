### 2026-10-14 00:00-01:30 第一段

**1. 修掉 pmux_onehot 的假失败（生死线）**
- 不是功能不等价：EQY 按名字匹配内部信号 `sel`，而我们的 pass 让 `sel` 变成悬空线。
- 定位靠 `eq/partition.list`（失败分区是 `pmux_onehot.sel.0` 而不是 `y`）+ SAT 反例表。
- 修法：产出网表前统一 `opt_clean -purge`。6 用例全 PASS。
- 详见 reports/007。

**2. 算法泛化：支持多个缺码**
- 原来 `case` 里 default 覆盖多个码就跳过（`n_missing > 1`）。其实缺码叶子各填一份 A 即可。
- 去掉这个限制，`scale_sparse32`（32 码只列 12 个）收益从 0% 变成 −50.5%。
- `-max_leaves` 默认 16 → 64（原来 5/6 位选择总线直接跳过）。

**3. 千级节点用例生成器**
- `scripts/gen_cases.py` → 7 个规模化用例（rtl/scale/，默认流程 407~1117 单元）。
- 含全码 case、稀疏 case、多 mux 共享总线、类 ALU、两级嵌套 case。

**4. 重大发现：收益高度依赖映射口径（reports/008）**
- 默认 synth 的 ABC 是延迟导向，且 `&fraig/scorr/dc2` 会把规则 mux 树打散成零散门。
  实测 pmux_opt 输出的 504 个 `$_MUX_`，经默认 ABC → 980，经 gate_area → 1150，
  只有最小化的面积导向脚本能保住 504。
- 换成「面积导向 + 不打散 mux」的映射后：13 用例 5227 → 2829，**−45.9%**（默认口径是 −23.7%）。
- 新增 `scripts/bench_flows.py`，同时量 4 种口径；`scripts/regress.sh` 支持 `PMUX_MAP=`。
- ⚠️ LUT 口径下目前几乎没有收益（2216 → 2201），这条风险已写进 reports/008，需要向组委会确认计数口径。

**5. 工具与踩坑记录**
- `scripts/cellcount.py`：从 stat 输出读单元数（避免 grep 在 BSD 下的坑）。
- `scripts/abc_mux_keep.abc` / `abc_gate_area.abc` / `abc_lut_area.abc`。
- 坑1：macOS 没有 `timeout`，regress.sh 改用 perl alarm。
- 坑2：ABC 脚本注释必须用 `#`，用 `;` 会报错；**ABC 报错时 Yosys 不中断**，会静默给出未映射结果 → bench_flows.py 里加了检测。
- 坑3：ABC 的 `&if` 是 LUT 映射、`&nf` 才是门级映射，两者数出来的东西不可比。

**7. 随机模糊测试（scripts/fuzz_equiv.py）**
- 自动生成随机常量解码型 PMUX（宽度/覆盖/嵌套/与逻辑混排/反相总线），逐个跑
  「优化流程 → EQY」。
- 累计 **112 个随机用例全部等价**（种子 20261014 与 777，可复现）。
- 副产品：撞出了「改写后反而变差」的用例（fuzz_033 4 位总线只列 3 个码、数据 16 位，+31.6%）。

**8. 代价模型 + 自动选优**
- pass 里加了代价模型：先算「常量折叠后真正剩下多少个 mux 节点」，
  再与「与或网络 + 比较器」的估算比，估算明显不划算（>1.5 倍）就跳过。
  效果：fuzz_033 从 +31.6% 变 0（跳过），13 个主用例数字不变。
- 但模型终究粗（ABC 还会再变一层），所以流程脚本 `pmux_synth.sh` 默认开 `PMUX_AUTO=1`：
  **两条流程都跑、取单元数更小的那份** → 最坏情况也不劣于基准。

**9. 交付脚本**

- `scripts/cellcount.py`：从 yosys 日志读**最后一个** "N cells"（坑：synth 内部也打一次）。
